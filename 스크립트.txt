# 발표 스크립트: AI 기반 소스코드 보안점검 도구

안녕하세요. 저희가 개발 중인 **AI 기반 소스코드 보안점검 도구**를 소개하겠습니다.

이 도구는 Java, JavaScript, JSP 등의 소스코드를 분석해 보안 취약점 후보를 찾고, 점검 결과를 보고서로 제공하는 프로그램입니다.

## 1. 개발 배경

소스코드 보안점검은 취약한 코드를 찾아 수정하는 데 도움이 되지만, 점검 결과를 사람이 일일이 확인하고 정리하는 데 시간이 걸립니다.

저희는 기존 정적 분석 규칙에 사내 Qwen 모델을 활용한 AI 분석을 더해, 취약점 후보와 그 근거를 한곳에서 확인할 수 있는 도구를 만들고자 했습니다.

사내 VDI에서는 외부 AI 서비스에 접속할 수 없기 때문에, 외부 ChatGPT를 이용해 코드를 작성하고 GitHub에 올린 뒤 VDI에서 내려받아 VS Code로 실행하는 방식으로 개발하고 있습니다. 실제 점검에는 사내 환경에서 접근 가능한 Qwen을 사용합니다.

## 2. 프로그램 구성

프로그램은 크게 네 부분으로 구성됩니다.

1. **Streamlit 화면**: 점검할 소스 폴더를 선택하고 점검을 시작합니다.
2. **규칙 기반 분석**: 미리 정의된 보안 규칙으로 코드에서 취약점 후보를 찾습니다.
3. **AI 분석**: 사내 Qwen이 발견된 코드와 주변 문맥을 분석해 결과를 보완합니다.
4. **보고서 생성**: 점검 결과를 화면에 요약하고 HTML 보고서로 저장합니다.

전체 흐름은 다음과 같습니다.

```text
사용자가 소스 폴더 선택
        ↓
규칙 기반 코드 점검
        ↓
Qwen을 이용한 결과 분석
        ↓
화면에 요약 표시 및 보고서 생성
```

## 3. 점검 과정

사용자는 Streamlit 화면에서 점검할 소스코드를 지정한 다음 **보안점검 시작** 버튼을 누릅니다.

점검이 진행되는 동안 화면에 진행 내용이 표시되고, 완료되면 취약점 요약과 생성된 보고서 위치를 확인할 수 있습니다. 버튼은 점검 중에는 다시 실행되지 않도록 비활성화되고, 점검이 끝나면 다시 사용할 수 있도록 구성했습니다.

규칙 기반 분석은 코드 패턴을 빠르게 검사하고, Qwen 분석은 해당 코드가 어떤 맥락에서 사용되는지 살펴봅니다. 두 결과를 함께 확인해 취약점 후보를 검토할 수 있습니다.

## 4. GitHub 자동 점검 검토

처음에는 GitLab에 코드를 push할 때 자동 점검을 실행하는 방안을 검토했습니다. 하지만 프로젝트에 실행할 수 있는 GitLab Runner가 할당되어 있지 않아 진행하기 어려웠습니다.

이후 GitHub에 push할 때 자동 점검을 실행하는 방식도 검토했습니다. 그러나 현재 점검 과정은 사내 네트워크에서 사용하는 Qwen에 연결해야 합니다. GitHub의 일반 실행 환경에서는 사내 Qwen에 접근할 수 없으므로, 현재 환경에서는 AI 분석을 포함한 자동 점검을 안정적으로 실행하기 어렵습니다.

따라서 자동 실행 기능을 실제로 도입하려면 사내 네트워크에서 실행되는 별도 Runner를 준비하거나, 네트워크 접근 구조를 마련해야 합니다. Runner와 사내 시스템의 접근 권한은 회사 환경과 보안 정책에 따라 검토가 필요합니다.

## 5. 현재 상태와 향후 계획

현재는 개발자가 소스를 내려받아 사내 VDI에서 실행하고, Qwen에 연결해 점검하는 방식이 현실적인 사용 방법입니다.

향후에는 다음을 검토할 수 있습니다.

- 점검 결과와 보고서 형식 개선
- 사내 환경에서 사용할 전용 자동 점검 Runner 구성 검토
- AI 분석 없이 실행하는 규칙 기반 점검과 Qwen 분석을 분리할 수 있는지 검토
- 보안 담당자가 결과를 더 쉽게 검토할 수 있도록 결과 화면 개선

자동 점검은 소스를 push하기만 하면 바로 실행되는 방식으로 보이지만, 실제로는 점검 환경이 소스 저장소와 Qwen 양쪽에 접근할 수 있어야 합니다. 따라서 기능 구현뿐 아니라 실행 환경과 네트워크 접근 조건이 함께 갖춰져야 합니다.

## 6. 마무리

이 프로젝트는 규칙 기반 분석과 사내 Qwen을 결합해 소스코드 보안점검을 지원하는 도구입니다. 현재는 Streamlit 화면을 통해 직접 점검을 실행하는 형태이며, Git push 기반 자동 점검은 Runner와 사내 Qwen의 연결 문제를 해결한 뒤 추진할 수 있습니다.

발표를 마치겠습니다. 감사합니다.
